Its complete `LICENSE` and `NOTICE` files are copied verbatim into `assets/third-party/codex/` in every APK and are independently accepted only at SHA-256 `d17f227e4df5da1600391338865ce0f3055211760a36688f816941d58232d8dc` and `8228749dd4dd6026baed0442f80e911308430478449285c865b188d97e6a013c`.

The unchanged Codex 0.148.1 package tarball is downloaded from the npm registry and accepted only when its SHA-256 is `b68a6c6770752deb045db084a9637b8cf1647b996a57d454e599981b963c4092`; this is the same digest published for the GitHub release asset. Android installs executable APK payloads from the native-library directory only under `lib<name>.so` names, while this exact Codex version still hard-codes the sibling name `codex-code-mode-host`. AGENTCODI therefore makes one disclosed, equal-length binary data-field substitution in the already verified app-server: `codex-code-mode-host` becomes `libcodex-codehost.so`. The untouched source app-server, untouched host, and resulting Android app-server are accepted only at SHA-256 `35c76bc8a75fc768ea44433bcc755be931a3d73215d8324a182020b57ff1aa49`, `da7bc9b805dd069f9b4008cb749d0f192cfd83445ed6ba7202ffd5aa51c1f855`, and `9c74afbfa027b840228278f4483405f59dc03393185e6e3a52fbc7ca64b921b9`, respectively. No runtime code, authorization behavior, host bytes, or license text is otherwise changed. Original AGENTCODI Java/C++ code remains distinct from this compiled third-party runtime.

Since AGENTCODI 0.4.7, the APK also contains the compiled Android ARM64 Node.js LTS 24.18.0 toolchain from the Termux package repository. It is packaged because Android 10 and newer do not permit execution from the app's writable home. AGENTCODI never downloads, synthesizes, or replaces this executable at runtime. The user or an explicitly approved Codex command only creates an owner-only activation marker below `workspace/toolchain`; before activation the shell explains that user permission is required.

The accepted package SHA-256 values are Node.js `6456b78aba9e0007de7a4c580d2b34bb3865145bebe06e75273152f8dcba4236`, c-ares 1.34.8 `7681fc23e822d7988ba8b2adf3468f93ae68f724dda365cff1385096a9fa87e6`, ICU 78.3 `f536403f65a08fe0df6e7304184e902d54def77d5c3bd5edfd9109d57601d276`, SQLite 3.53.4 `0e909ce0d50fe123305446cd22e0c5edf535d40344b9b065fbdcdee52f53198d`, OpenSSL 3.6.3 `86760e9ce736f463236f2c15b1eb3a3fdcfc5778d0fd7077a917448dcc90f3aa`, and zlib 1.3.2 `75e7d0af17fcc3b40004309fdc00a1ddb9ae08346dce5e269902c34ac3966ac9`. The build performs reviewed equal-length ELF dependency-name relocations so Android can extract the versioned shared libraries under `lib*.so` names, then verifies every resulting runtime file against its documented derived SHA-256 before packaging.

In 0.5.18 the private native-library directory is removed from command `PATH`, and the actual Node.js, Python, and ripgrep executable ELFs each acquire one mandatory AGENTCODI C++ policy-guard dependency before packaging. Each derived ELF also contains a relocation-free first-party entry attestor in a separate 16-KiB-aligned read/execute segment. It opens the genuine no-follow sibling guard and verifies that file's device and inode against an executable process mapping before continuing to the original entry; this rejects an `LD_LIBRARY_PATH` substitute that would otherwise suppress the guard constructor. The pre-attestation and final Node.js ELFs are accepted at SHA-256 `cbf6b5c9aade3efd2127cb610db4a9ab8d54860c26d2c1273f8e3fae0bd6719f` and `6d1e83f6dd9586adaee78d17f6bac23870af6a21ccad58779bac270cc318614c`, and the final Python executable at `bfbaf0ac9a9cbda86f366537430ca8db41c0100f15b2cc4ce3674f948f7a3e35`. The Node.js, Python, and ripgrep guard libraries are accepted at `92d7e6740a494c687383c83c1109f133b04ac67d0ac6a0714c6c7e26a5c3e1a7`, `ab8ab4014503943c14842e79507cb5975b270f4fb97cec3c3fe423ad1fe71814`, and `6f38c49ad156e456248330bfddec2dc3f934f94884cd64d1fd751c08fee40a20`; their attestor payloads at `241c3c157251f94d682da6bad6082079786198d241f63be76a456c8c64f16dfa`, `7e275cc1b169871b100a15f82af1395f384b507234549241ad14c98a94cb762c`, and `206e3f43a6dd1cfa1b81cc901e86be00d19c1584866f864da9ff94e6defcba99`.
