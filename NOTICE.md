# Provenance

AGENTCODI original Java/C++ application code, tests, resources, build automation, and documentation are Copyright 2026 Pascal (Mc Pasi) and licensed under the Apache License, Version 2.0. The complete terms are in `LICENSE` and are displayed in the APK's legal-notices screen.

Since AGENTCODI 0.3.2, the app packages the separately licensed Android ARM64 Codex CLI/app-server community build `@mmmbuto/codex-cli-termux` 0.147.2, including its matching `codex-code-mode-host`; AGENTCODI 0.5.8 retains that exact pinned artifact. It is an Android/Termux distribution fork of OpenAI Codex, not an official OpenAI Android APK. OpenAI Codex is Copyright 2025 OpenAI; the Android/Termux compatibility work is Copyright 2026 Davide A. Guglielmi. The artifact is distributed under Apache License 2.0. Its complete `LICENSE` and `NOTICE` files are copied verbatim into `assets/third-party/codex/` in every APK.

The Codex artifact is downloaded from the npm registry and accepted only when its SHA-256 is `4b70bca7004402cf445670efe43775e76ac598f719c72a8d6c83ac8494bb2b5c`. Android installs executable APK payloads from the native-library directory only under `lib<name>.so` names, while this exact Codex version hard-codes the sibling name `codex-code-mode-host`. AGENTCODI therefore makes one disclosed, equal-length binary data-field substitution in the already verified app-server: `codex-code-mode-host` becomes `libcodex-codehost.so`. The untouched source app-server, untouched host, and resulting Android app-server are accepted only at SHA-256 `c95b61282ed0086b9895b8d401fda274ef9ddf1a80fe808f3fad93f4444d8dc4`, `aa90fc2ce11bc309a08ea25836019fda6c7ff7edc9eaa35f8f3746a37979fc18`, and `11db4fdd763e21fa81f4fb47d61c4bcbea145e817364eaa35f6e75146f85beee`, respectively. No runtime code, authorization behavior, or license text is otherwise changed. Original AGENTCODI Java/C++ code remains distinct from this compiled third-party runtime.

Since AGENTCODI 0.4.7, the APK also contains the compiled Android ARM64 Node.js LTS 24.18.0 toolchain from the Termux package repository. It is packaged because Android 10 and newer do not permit execution from the app's writable home. AGENTCODI never downloads, synthesizes, or replaces this executable at runtime. The user or an explicitly approved Codex command only creates an owner-only activation marker below `workspace/toolchain`; before activation the shell explains that user permission is required.

The accepted package SHA-256 values are Node.js `6456b78aba9e0007de7a4c580d2b34bb3865145bebe06e75273152f8dcba4236`, c-ares 1.34.8 `7681fc23e822d7988ba8b2adf3468f93ae68f724dda365cff1385096a9fa87e6`, ICU 78.3 `f536403f65a08fe0df6e7304184e902d54def77d5c3bd5edfd9109d57601d276`, SQLite 3.53.4 `0e909ce0d50fe123305446cd22e0c5edf535d40344b9b065fbdcdee52f53198d`, OpenSSL 3.6.3 `86760e9ce736f463236f2c15b1eb3a3fdcfc5778d0fd7077a917448dcc90f3aa`, and zlib 1.3.2 `75e7d0af17fcc3b40004309fdc00a1ddb9ae08346dce5e269902c34ac3966ac9`. The build performs reviewed equal-length ELF dependency-name relocations so Android can extract the versioned shared libraries under `lib*.so` names, then verifies every resulting runtime file against its documented derived SHA-256 before packaging.

Node.js is distributed under the MIT License together with the third-party terms in its upstream `LICENSE`; c-ares uses an MIT-style license; ICU uses the Unicode License v3 and accompanying third-party terms; OpenSSL uses Apache License 2.0; zlib uses the zlib License; and SQLite is dedicated to the public domain. Their complete applicable license texts are copied into `assets/third-party/node/` in every APK that bundles the Node.js toolchain. The Node.js, ICU, and OpenSSL license inputs are independently SHA-256 pinned; the c-ares and zlib notices come from their verified packages. SQLite's public-domain status is disclosed in the packaged third-party notice.

AGENTCODI 0.5.8 retains the native PNG validator's link to that same already packaged, pinned, and attributed zlib 1.3.2 shared library. This adds no new third-party artifact or license family. The SHA-256 materialization-proof implementation added in 0.5.5 is AGENTCODI C++ source, the bounded workspace-import implementation added in 0.5.6 is AGENTCODI Java source, the 0.5.7 model-context correction is AGENTCODI Java source with Java/C++ test coverage, and the 0.5.8 returned-grant validation is AGENTCODI Java source with Java and architecture test coverage; none introduces a third-party component.

AGENTCODI 0.4.10 additionally packages npm 11.19.0 from the verified Termux package with SHA-256 `385a051111f66c56d0564e6809244f1740427805a78d2e5a5dc470fb420832f8`. npm executes only through the packaged Node.js runtime. Its bundled runtime files and dependency license texts remain third-party material; the aggregate license bundle is copied to `assets/third-party/npm/NPM-LICENSES`.

AGENTCODI 0.4.10 also packages Python 3.14.6-1 from the verified Termux package with SHA-256 `3166e56c2b6c03fff41191fbb9d736302978e7c484702814d9f6dc99dd6006bd`. Its retained packages are independently pinned: libandroid-posix-semaphore `0efa8677a0166315ba4e685863712eba0ca0a1732827492f38226e2723730c7a`, libandroid-support `f2f145d6135ad4843ac9670153be3e3944dc1e6f1736d46d2306c28f2b86f517`, libbz2 `4335d7f060650b0aabef545d1334c2f9f280223d5962e13c24a00ec934b794ba`, libffi `8c8c1d6ffb049d8496a21c1202d9b4dc9145140886fdbb45716684565f4ed3f5`, liblzma `594925a313879f590fbd24050305551a78eadd9a9319f6e612389b1a521113c6`, ncurses `f44bbfdc3d42ec0217bffa978309390e59cea5a48a9a83226d4a496c42ad0b99`, ncurses-ui-libs `7393f369009be189b3d4ec1f9b16ebd57621d6a1b22949ae07685573950d1f37`, zstd `e1b4a5113648da8de189620ba1fce74c48b2d0833d9043391b9a1c91fb606fd3`, and the shared expat/OpenSSL/SQLite/zlib inputs listed above. The optional `_dbm`, `_gdbm`, and `readline` extension modules and the gdbm/readline runtime packages are not downloaded or bundled.

The build compiles the Python standard library to bytecode, preserves npm's own bundled runtime data, relocates 72 native Python extension modules into Android-installable `lib*.so` files, and constructs a strictly bounded manifest of every regular runtime file and native link. Python's standard-library `dbm` selects its SQLite backend, `shelve` remains functional, and the modern PyREPL provides interactive editing without native Readline; all three paths are executed during the APK build. The build also rejects any gdbm/readline filename, ELF dependency, runtime-manifest record, or APK entry. The derived manifest is pinned at SHA-256 `e7fa5752f739c96cde42b20b38ae57d7249eb535b1524b5fc5a7be73d1008e7a`; the complete derived Python native-set listing is pinned at `415a1309d17f45bdb6ba1cf061f24d75e8b591430eda883e7e4e3f313a291b9a`. At first runtime start, Java verifies sizes, SHA-256 values, canonical containment, permissions, link count, and native targets before atomically materializing the private runtime outside workspace and `CODEX_HOME`. Activation only writes exact owner-only markers below `workspace/toolchain`; it never downloads or replaces these runtimes.
